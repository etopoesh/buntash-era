# Бунташный век


Ролевая игра для 7х классов. Дети делятся на рода, выбирают сословие (бояре/дворяне) и проходят исторические события XVII века, принимая решения, которые меняют их ресурсы: Слава, Крестьяне, Золото.


Игра открывается в браузере на планшетах/компьютерах — ничего устанавливать не нужно. Все данные хранятся в Firebase Realtime Database, поэтому прогресс синхронизируется между всеми устройствами в реальном времени.


## Структура файлов


| Файл | Что внутри | Кто обычно правит |
|---|---|---|
| `index.html` | разметка страницы, подключение скриптов | разработчик |
| `style.css` | всё оформление | разработчик / дизайнер |
| `events.json` | **контент**: тексты событий, выборы, исходы | учителя истории |
| `firebase-init.js` | подключение Firebase, сохранение/загрузка состояния | разработчик |
| `state.js` | модель данных, общие переменные, вспомогательные функции | разработчик |
| `view-rod.js` | экраны рода: главная, вход, кабинет | разработчик |
| `view-gm.js` | панель ведущего | разработчик |
| `main.js` | общий цикл рендера и запуск приложения | разработчик |


**Порядок подключения скриптов в `index.html` важен** — `main.js` использует функции из всех остальных файлов, поэтому он должен идти последним:


```html
<script src="firebase-init.js" defer></script>
<script src="state.js" defer></script>
<script src="view-rod.js" defer></script>
<script src="view-gm.js" defer></script>
<script src="main.js" defer></script>
```


## Как это работает


- **Один общий `state`** хранится в Firebase (`stateRef`) и синхронизируется на все открытые вкладки в реальном времени через `stateRef.on('value', ...)` в `main.js`.
- **`events.json` не хранится в Firebase** — он подгружается напрямую с сайта при каждой загрузке страницы (`loadEvents()` в `firebase-init.js`). Это значит: чтобы обновить тексты событий, достаточно отредактировать `events.json` и запушить — ничего в базе данных трогать не нужно.
- **Каждый род** проходит события в своём темпе (поле `progress` у рода), а не одновременно со всеми — кроме глобальных событий, где итог наступает только тогда, когда ведущий сам нажмёт кнопку оглашения.


## Схема событий (`events.json`)


Два типа событий — `"type": "normal"` и `"type": "global"`.


**Обычное событие** — выбор сразу даёт свой исход:
```json
{
  "id": "salt",
  "type": "normal",
  "era": "1646 год",
  "title": "Соляные рудники",
  "description": "...",
  "choices": [
    {
      "key": "invest",
      "label": "Вложиться в рудники",
      "effect": { "zoloto": 15, "krestyane": -10 },
      "outcomeTitle": "Соляной бунт!",
      "outcomeText": "..."
    }
  ]
}
```


**Глобальное событие** — у выбора есть мгновенный личный эффект (`effect`/`outcomeTitle`/`outcomeText`, как у обычного), а отложенный эффект наступает позже, когда ведущий жмёт «Огласить итоги». Отложенный эффект зависит от того, **что выбрал сам род**, а не от того, оказался ли он в большинстве — это задаётся через `effectByChoice` внутри `outcomes`:
```json
{
  "id": "war",
  "type": "global",
  "choices": [
    { "key": "war", "label": "За войну", "effect": {...}, "outcomeTitle": "...", "outcomeText": "..." },
    { "key": "peace", "label": "За мир", "effect": {...}, "outcomeTitle": "...", "outcomeText": "..." }
  ],
  "outcomes": {
    "war": {
      "narrative": "Если победило большинство 'война' — вот что происходит со всеми",
      "effectByChoice": {
        "war": { "...": "эффект для тех, кто голосовал за войну" },
        "peace": { "...": "эффект для тех, кто голосовал за мир" }
      }
    },
    "peace": { "narrative": "...", "effectByChoice": { "war": {...}, "peace": {...} } }
  }
}
```
Ресурсы: `slava`, `krestyane`, `zoloto`. Указывайте только те, что меняются — знак определяет прибыль/потерю.


## Данные рода


Каждый род в `state.rods` хранит: `resources` (текущие ресурсы), `estate` (`boyare`/`dvoryane`), `progress` (на каком событии находится), `answers`/`votes` (сделанные выборы), `seenReveal` (какие итоги глобальных событий уже показаны).


## Локальный запуск


Файлы статические, но `fetch('events.json')` не работает при открытии `index.html` напрямую с диска (`file://`) — нужен локальный сервер:
```
python3 -m http.server 8000
```
и открыть `http://localhost:8000`.


## Деплой


Сайт публикуется через GitHub Pages — при пуше в основную ветку изменения появляются на сайте автоматически.


## Firebase


Конфиг лежит в `firebase-init.js` (`databaseURL`). База — Realtime Database, публичные правила чтения/записи (без авторизации), потому что игра рассчитана на класс, а не на публичный интернет — при желании ужесточить это отдельная задача.
